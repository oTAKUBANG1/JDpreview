# 2026-11-05 · v0.1.3 导入链路

## 18:00 开工

- 下午已交付 v0.1.2（权重/硬门槛/评分卡），本轮接 P1。
- 决策：PDF/OCR 放浏览器端，服务端只保留「链接抓取」一个联网能力——简历不出机器，服务器也不背 CPU。

## 18:20 依赖与 vendor

- `pdfjs-dist@6.5.438`、`tesseract.js@7.0.0` 装成 devDependencies，只用于生成静态资源。
- `scripts/vendor-assets.mjs`：复制 pdf.js legacy build、tesseract worker+三种 wasm 核心（simd / relaxedsimd / 普通），下载 chi_sim+eng 的 `4.0.0_fast` 语言包。
- 取舍：语言包用 fast（1.6+1.9MB）而不是 best（20+10MB）。识别清晰截图够用，首屏加载快一个数量级。
- `public/vendor/` 不入库（25MB 二进制），改由 `npm run vendor` 生成；README 与 DELIVER 写清步骤。

## 19:00 踩坑

1. tesseract ESM 只有 default 导出，`mod.createWorker` 是 undefined → 改成 `mod.default ?? mod`。
2. worker 按浏览器能力挑核心，第一次只 vendor 了 simd，报 `relaxedsimd-lstm.wasm.js failed to load` → 补齐三种变体。

## 19:20 浏览器验收

- 装 puppeteer-core，写 `scripts/browser-verify.mjs`：真实 Chrome 里跑 PDF 抽取 + OCR，同时截桌面/手机两张图。
- 结果：PDF 201 字；OCR 207 字、置信度 84，`AI` 被识成 `Al`，验证了“OCR 结果先人工核对”这条设计的必要性。
- 移动端 390×844 截图检查：单列、按钮换行、无横向滚动。

## 19:40 链接导入

- `/api/fetch-url`：8 秒超时、2MB 上限、最多 3 次重定向逐跳校验；拒绝私网/回环/链路本地；只认 text/html。
- 抓取失败按场景给中文提示：登录墙 401/403/429 → “改用截图识别”。
- 单测用本地 stub 服务覆盖成功与 403 两种情况（allowPrivate 仅测试用）。
