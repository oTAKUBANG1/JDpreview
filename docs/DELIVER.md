## 2. 技术说明

- **运行时**：Node.js ≥ 20，零第三方依赖；`node:http` 自带服务，`node:test` 自带测试。
- **前端**：原生 ES Module + CSS，无构建、无框架。理由是 MVP 要在断网环境"克隆即跑"，框架只会增加交付面。
- **结构**：engine 五个模块职责单一、纯函数、可注入依赖；`pipeline.analyze(input, deps)` 因此能在不碰网络的情况下测循环保护。
- **为什么不直接用 LLM 做改写**：自由改写会让"事实一致率"失去可验证性，MVP 的差异点恰恰是"可验证"。v0.2 接模型后，本仓库的规则引擎转为**确定性闸门**，模型输出必须过它。

关键取舍：

| 决策 | 选了 | 否掉 | 理由 |
|---|---|---|---|
| 改写动作 | 只重排 + 白名单术语替换 | 自由重写/删减 | 保证每处改动可机器核验；删内容不可逆 |
| 术语对齐范围 | 手写 SAFE_ALIGN（14 对） | 全量同义词替换 | 「灰度发布→A/B测试」这类替换会改事实语义 |
| 事实一致率分母 | 断言数（改动+数字+实体） | 全文字数/句子数 | 与源规格一致，且能解释是哪条断言没过 |
| 测试运行方式 | `node test/all.js` 单进程 | `node --test test/` | DSH 沙箱下子进程 stdio 管道被拒（EPERM）；单进程等价且更快 |

## 3. 使用说明（已实测）

```bash
cd D:\JDpreview
node src/server.js          # 输出 http://127.0.0.1:3080
```

1. 打开 `http://127.0.0.1:3080` → 点「加载示例」→「开始分析」。
2. 看结论徽章：建议补充后投递（示例 JD 要求大模型/Prompt/RAG，示例简历没有）。
3. 切「待补清单」：3 条 must 问题可直接复制去补简历。
4. 点「诱导编造测试」再分析：JD 要 3 年 AI 产品+百万 DAU，简历只有售后支持；改写稿不会出现这些词，全部进待补清单。

`npm test` / `node test/all.js`：30 个用例全绿（实测 2026-11-04）。
