## 2. 技术说明

- **运行时**：Node.js ≥ 20；服务端零框架（`node:http`）。构建期依赖只有 pdf.js / tesseract.js / puppeteer-core，全部用于生成本地静态资源与验收。
- **前端**：原生 ES Module + CSS，无构建、无框架。
- **结构**：engine 模块职责单一、纯函数、可注入；`pipeline.analyze(input, deps)` 可离线测循环保护；`public/importers.js` 负责 PDF/DOCX/OCR；`src/fetcher.js` 负责链接抓取。
- **离线**：`npm run vendor` 把 pdf.js、tesseract 三种 wasm 变体和 chi_sim/eng 语言包复制到 `public/vendor/`（约 25MB，不入库），页面不请求 CDN。
- **有状态部分**：岗位池用 `node:sqlite`，数据在 `data/jdpool.sqlite`（gitignore）。部署时要挂载持久盘并纳入备份；推荐只读 JD，不存简历。

关键取舍：

| 决策 | 选了 | 否掉 | 理由 |
|---|---|---|---|
| 改写动作 | 只重排 + 白名单术语替换 | 自由重写/删减 | 保证每处改动可机器核验；删内容不可逆 |
| 术语对齐范围 | 手写 SAFE_ALIGN（13 对） | 全量同义词替换 | 「灰度发布→A/B测试」这类替换会改事实语义 |
| 事实一致率分母 | 断言数（改动+数字+实体） | 全文字数/句子数 | 与源规格一致，且能解释是哪条断言没过 |
| PDF/OCR 位置 | 浏览器本地 | 服务端 | 简历不出机器；服务器成本最低 |
| 语言包 | tessdata_fast（1.6+1.9MB） | 4.0.0 best（20+10MB） | 截图清晰文本够用，加载快一个数量级 |
| 链接抓取 | 服务端抓 + SSRF 防护 | 纯前端抓 | 绕过 CORS；服务端必须做内网地址拦截 |

## 3. 使用说明（已实测）

```bash
cd D:\JDpreview
npm install
npm run vendor
node src/server.js          # http://127.0.0.1:3080
```

1. 「加载示例」→「开始分析」，看结论徽章、硬门槛比对、四张打分卡。
2. 「上传 PDF / DOCX」导入 JD 或简历；「截图识别」导入 JD 截图（OCR 后先核对再分析）。
3. 粘贴公开 JD 链接 →「导入链接」；遇到登录墙会提示改用截图。
4. 「编造风险测试」：JD 要 3 年 AI 产品 + 百万 DAU，简历只有售后支持 → 结论直接「不建议投递」（硬门槛不满足），改写稿零编造。

验证记录（2026-11-05）：

- `node test/all.js`：45 用例全绿
- `node scripts/browser-verify.mjs`：PDF 抽取 201 字、OCR 207 字（置信度 84），桌面/手机截图各一张

## 4. 已知限制与后续

| 优先级 | 问题 | 影响 | 预估 |
|---|---|---|---|
| P0 | 词库覆盖有限（约 70 个能力项） | 小众岗位能力项抽不全 | 词库增量维护 |
| P0 | 规则改写不改善措辞，只调顺序 | 简历质量提升有限 | v0.3 接 LLM + 操作级闸门 |
| P1 | 扫描件无文字层，只能 OCR | 手写/低清截图识别差 | 接视觉模型或更高精度语言包 |
| P1 | 长句能力词子串匹配可能误命中 | 证据判定偏宽 | 轻量分词 |
| P1 | 无历史记录、无导出 PDF | 复用体验弱 | 档案本地存储（v0.2 设计已出） |
| P2 | 链接导入抓不到登录墙站点 | BOSS 直聘等不可用 | 截图 OCR 兜底 |
