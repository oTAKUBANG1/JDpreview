# 简历 × JD 对齐 Agent —— 产品需求文档（MVP v0.1）

## 1. 一句话

求职者把一份 JD 和一份简历粘进来，5 分钟内拿到三件事：**这份岗能不能投**、**怎么把真实经历往 JD 上对齐**、**JD 要但我没有的到底是什么（以及该拿什么话去补）**。

## 2. 为什么是现在

既有的「简历润色 / 一键优化」类工具，优化目标是"看起来匹配"，代价是往简历里塞 JD 关键词。面试官一问就穿帮，且求职者自己无法事后核验哪一句是编的。

本产品的差异点不在改写能力，而在**约束**：

- 事实唯一来源是原简历，JD 只决定"写什么、怎么排"，不提供事实；
- 每一处文字改动必须能追溯到原简历的一句话（Fact Ledger）；
- JD 要而简历没有的，一律不许写进改写稿，只能进待补清单并向用户提问。

一句话：**宁可少改，不许编。** 打分卡里"事实一致率"一票否决。

## 3. 用户与场景

| | |
|---|---|
| 核心用户 | 1–8 年经验、正在跳槽/转岗的求职者（MVP 先覆盖产品、数据、技术岗） |
| 次级用户 | 简历代改/求职辅导从业者（后续按份收费场景） |
| 触发场景 | 看到一条心仪 JD，想判断值不值得投、怎么改简历 |
| 频次 | 一次求职周期内 10–50 次 |
| 现有替代 | 手动对照 JD 改 30–60 分钟/份；通用 AI 润色（快但会编） |

## 4. 目标与非目标

**MVP 目标**

1. 单次分析 < 3 秒，全本地运行，无 key 可用。
2. 给出四维打分卡 + 可投递结论（口径见 §6）。
3. 改写动作限定在「重排 / 同义术语对齐 / 标注无关项」，不做自由重写 —— 因此事实一致率天然可验证。
4. 待补清单里的每个问题都能被用户一句话回答。
5. 校验闸门独立于改写器，且能被单独测试（含人为注入幻觉的用例）。

**非目标（本期明确不做）**

- PDF/Word 解析上传（只收纯文本粘贴）
- 账号、云端存储、多份简历管理
- 自动投递、招聘网站抓取
- LLM 自由改写（留接口，v0.2 再接；见 §9）
- 英文简历

## 5. 核心流程

```
粘贴 JD + 简历
   ↓
① JD 解析：硬门槛 / 核心能力(权重) / 加分项 / 关键词库 / JD 自身缺陷
   ↓
② 对齐分析：逐条能力在简历里找证据句（含同义词），算覆盖/量化
   ↓
③ 对齐改写：按能力权重重排条目 + 同义术语统一 + 标无关项，逐处记 Fact Ledger
   ↓
④ 防幻觉闸门：溯源 / 升格 / 数字实体 / 贴标签 / 缺失泄漏，五道校验
   ↓
PASS → 交付 ｜ REVISE → 回 ③（≤3 轮）｜ BLOCK → 回退原文表述
   ↓
打分卡 + 对齐版简历 + 逐条改动 + 待补清单 + 校验报告
```

## 6. 打分卡口径（v0.1.2 起）

| 维度 | 计算 | 权重 |
|---|---|---|
| 事实一致率 | 通过断言数 / 总断言数 × 100（断言 = 改动条目 + 数字 + 技术实体） | 0.4，一票否决 |
| JD 对齐度 | 有证据的 must 能力项权重之和 / must 能力项权重之和 × 100 | 0.4 |
| 量化程度 | 含数字的证据句 / 证据句总数 × 100 | 0.2 |

能力项权重来源（v0.1.2）：

| 来源 | 基础权重 |
|---|---|
| 岗位名称命中 | 5 |
| 硬性门槛命中（学历/年限等） | 5 |
| 任职要求区 | 4 |
| 职责区 | 2 |

同一能力项重复出现或落在强调句里 +1，上限 5；`must` = 权重 ≥ 4。旧版的「关键词命中」与「JD 覆盖率」是同一套命中逻辑算两遍，已合并。

结论规则（按优先级）：

1. 硬门槛不满足（学历/年限）→ 不建议投递，并列出卡在哪一条；
2. 事实一致率 < 100 → 不建议投递；
3. must 能力项有缺口，或闸门未 PASS → 建议补充后投递；
4. 否则可投递。

限定领域年限（如「1 年 AI 产品经验」）规则版无法从简历自动核实，标「待确认」，不参与「不建议」判定。

| 编号 | 功能 | 优先级 |

## 8. 验收标准

1. 6 个用例全过，其中 T2「诱导编造」硬性要求：改写稿中不得出现原简历没有的年限、DAU、主导、AI 产品经历。
2. 空 JD 直接 FATAL 返回，不产出改写稿。
3. 人为构造的升格/数字篡改/贴标签改写稿必须被闸门拦下。
4. 循环上限生效，第 3 轮后强制收敛并在报告标注。
5. 页面刷新后能完整复现一次分析（示例数据一键填充）。

## 9. 后续路线

- v0.2：接 LLM（OpenAI 兼容），四段流水线原样搬；本仓库规则引擎降级为"确定性闸门"，负责在模型输出后复核。
- v0.3：PDF/Word 解析、历史记录、按 JD 批量出稿。
- v1.0：简历版本管理 + 投递转化回看（哪版简历拿到面试）。
